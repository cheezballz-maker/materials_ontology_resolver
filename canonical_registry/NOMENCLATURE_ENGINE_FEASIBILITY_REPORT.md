# Nomenclature engine feasibility

## Finding and recommendation

An isolated OPSIN trace is the smallest justified next experiment, **not** a production adapter. Public OPSIN output supplies atom locant values, and prior isolated instrumentation captured a narrow stereo-descriptor-to-fragment-to-CML-atom path. Neither establishes the general source-span, fragment-ownership, clone-lineage and candidate-atom chain needed for source-supported tautomer or charge claims. Test that chain for a bounded indicated-H/functional-group class, first pinning an exact matching OPSIN source build. Keep the current resolver and external gate unchanged.

OpenEye Lexichem is a credible secondary option: its documentation explicitly describes locant indices attached to atoms produced by name parsing. This is a documented programmatic capability, not a locally demonstrated source-span or ownership mapping. ACD/Labs and ChemAxon document name-to-structure products; their relevant semantic provenance remains unestablished here. No commercial product was installed or exercised, no license was obtained, and no project data was sent to a vendor.

## OPSIN bridge: public outputs and prior work

The [local source snapshot](opsin_ownership_followup_final/source_snapshot/opsin-core/src/main/java/uk/ac/cam/ch/wwmm/opsin/SmilesOptions.java) defines `CXSMILES_ATOM_VALUES` as the **first locant value of each atom**, distinct from CX atom labels. The writer emits `$_AV:` values in output atom order; the [probe](engine_probe_results.json) verifies that RDKit reads these as `molFileValue` properties. CML exposes locant labels on `a<ID>` atoms. Those labels can include generated numbering, element locants such as `O` and `O'`, repeated locants, and primed locants. They are not a map from a particular source text occurrence to its owner.

In `2-(2-hydroxyphenyl)ethanol`, the public CX output contains two different atoms labelled `2`; a source-token-to-fragment choice cannot be inferred from that value. `2,2'-bipyridine` retains primed values, while the unlocanted name `triazine` produces numbered atoms with `SUCCESS` and no ambiguity flag: observed numbering is not evidence that the input supplied it. An absence of warnings is not proof of unambiguous source semantics. Public CML-to-RDKit graph isomorphism can also be nonunique under symmetry.

Earlier [fragment feasibility](OPSIN_FRAGMENT_OWNERSHIP_FEASIBILITY_REPORT.md) and [ownership follow-up](OPSIN_OWNERSHIP_TRACE_FOLLOWUP_REPORT.md) already instrumented isolated copies of two private OPSIN classes. For R/S, they recorded processed descriptor nodes, candidate fragments and selected atom IDs, then matched IDs to the same result's CML. A nested repeated-locant example exposed an ordered/fallback candidate situation; a cloned 1:2 example lacked original-token lineage; a warning path and E/Z were not demonstrated. The source checkout has no pinned commit, and the source-built core was not proven byte-identical to the installed snapshot. This is narrower than a general ownership solution; repeating the same R/S trace would not establish indicated-H provenance.

The source snapshot's `OpsinResult.getStructure()` is package-private; public `getCml()`, `getExtendedSmiles()`, status and warnings are available. Internal parse/fragment objects require unsupported access or instrumentation. Any maintained fork carries patch, version, regression and source-provenance obligations; it must preserve selected parse identity, text offsets and clone/transform lineage rather than invent them after serialization.

## Standard InChI and FixedH

The installed OPSIN `NameToInchi` source requests `InchiFlag.FixedH` for non-standard InChI and omits it for Standard InChI. For the two locally generated `pyridin-2(1H)-one` and `pyridin-2-ol` candidates, Standard InChI is equal while non-standard outputs differ in their `/f/` hydrogen layer. This demonstrates preservation of **that candidate-graph distinction**, not source-name proof or universal tautomer discrimination. The `1H-pyrazole` and `2H-pyrazole` probes yielded the same FixedH string in this test; labels and symmetry must not be treated as evidence of distinct substances. Some outputs have no `/f/` layer at all. FixedH remains an inspection/comparison representation, not evidence that a source explicitly established a proton location. See also [IUPAC tautomerism](https://goldbook.iupac.org/terms/view/T06252) and [IUPAC P-14.7](https://iupac.qmul.ac.uk/BlueBook/P1.html).

## Experiments actually run

[Probe script](nomenclature_engine_feasibility/run_probes.py), [Java harness](nomenclature_engine_feasibility/Probe.java) and [raw structured outputs](engine_probe_results.json) retain 26 local, default-configuration OPSIN probes, including CML, CXSMILES, warning flags, Standard and non-standard InChI. Sixteen are independent controls: indicated-H and lactam/lactim contrasts; acid/sodium salt and diamine dihydrochloride; nested and primed locants; R/S versus unspecified stereo; ethanol/methanol; malformed trailing text; and unlocanted triazine. Ten are local representative or historical source probes. Expected claims and authoritative grounding are recorded per input; where source meaning is not proven the records say so.

The counterion challenge is material: `ethane-1,2-diamine dihydrochloride` yields two `Cl` components plus a neutral diamine graph, not a locally verified ion-pair interpretation. The malformed name fails; the relative-stereo historical name and sulfate/sulfite historical input also fail. Successful parsing does not close these source-form questions. An additional local **source-form helper**, not a resolver admission run, kept `(2R)-butan-2-ol` versus `butan-2-ol` supported with the alias marked broad, while `(2R)` versus `(2S)` produced `STEREO_DIFFERENT` and conflict. Neither comparison promotes an alias or overrides a missing identity dimension. No commercial engines were experimentally tested and no external chemistry provider was queried.

## Applicability and safety

All 81 cases are individually listed in [false_hold_engine_applicability.json](false_hold_engine_applicability.json): **57 potentially addressable with further work**, **24 insufficient evidence**, and **0 observed eligibility recoveries**. These are cautious feasibility triage labels based on blocker and name-pattern evidence, not validated mappings or extrapolated recovery rates. No case is asserted genuinely ambiguous solely from an engine output; no commercial-license limitation is used as evidence of chemical ambiguity. Three diagnostic-hold names were actually probed, without resolving all their source dimensions.

For 17504 the public parser again produces an anion; the earlier reference and acid-alias disagreement remain and this feasibility work does not make it exact. For 4373 OPSIN supplies a candidate and locants without proving source H specificity. For 30832 a candidate does not resolve the existing specific alias constitution conflict. 5684 and 5997 failed parsing; 23839 has the same historical source string as 5997, not a separately issued probe. 30142 and the historical dithiazole name parse, but the earlier form/stereo and tautomer concerns remain. These are implications for investigation, not new admissions.

## Proposed integration boundary and next proof of concept

The [recommended POC specification](recommended_mapping_poc.json) limits work to a disposable, pinned-source OPSIN build and an indicated-H/functional-group trace. It must connect **source span → selected parse node → owning fragment → source locant → same-result atom**, with explicit tracking across clones and transformations; include all mobile-H sites, charge, components and existing contradictions as independent checks. The trace is evidence for a separate identity comparator, not an identity decision and not a provider replacement. An OpenEye licensed comparison can later use the same challenges if access already exists; parser agreement alone is not proof.

Accept a bounded trace only if its exact source revision and build are reproducible, source offsets and graph mapping are independently verifiable, warnings and competing parses are retained, and independently grounded positive, negative, underspecified, repeated-locant, symmetric and conflict controls pass. Reject or abstain for untraceable clones, local fragment ambiguity, ambiguous graph isomorphism, default-as-explicit claims, or missing mobile sites. Historical unsafe cases must never become exact from the trace alone. This POC tests whether provenance is recoverable; it does not assume that a complete parser rewrite or fork is necessary.

## Integrity and handoff to main chat

The [integrity check](nomenclature_engine_feasibility/integrity_results.json) compares ontology, framework, OPSIN jar, schema and other contracts to the older freeze, checks frozen inputs and provider-cache hashes, and snapshots protected current resolver and evaluation files for the probe rerun. No production resolver, provider, ontology, schema, registry, OPSIN installation or frozen evaluation artifact was edited. The harness has no credential access and makes no network calls; its outputs contain names and public parser results only. Documentation was accessed read-only. No commercial binaries or proprietary source were retained.

**Demonstrated:** OPSIN public atom values and two controlled alias outcomes, plus the earlier narrow internal stereo trace. **Corrected assumption:** OpenEye documents atom locants from name parsing, while ACD rule highlighting and displayed numbering do not establish input-source provenance; FixedH preserves the tested candidate tautomer difference but is not source evidence. **Unknown:** general token ownership, original offsets, cloned lineage, source-versus-default semantics and complete form validation across all engines. **Exact next task:** pin a matching OPSIN build and run the bounded isolated indicated-H ownership/atom trace with the rejection criteria above, without changing admission.
