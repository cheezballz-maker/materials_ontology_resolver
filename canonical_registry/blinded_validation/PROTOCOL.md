# Blinded validation protocol

Locked before reference labels are frozen or predictions are compared. Date: 27 October 2026. Sampling seed: 20261027; review-set seed: 20261028.

The sampling steward reads engine categories only to assemble an admission census, provider-conflict census and stratified challenge sample. Adjudicators receive shuffled packets containing only numbered CUMA index, original preferred name and original aliases. No strata, engine structures, status, aliases, IDs or earlier reports are supplied. Three fresh agents have no prior conversation history and are instructed not to access prediction files. This is procedural input isolation, not an operating-system access barrier; the agents share a filesystem. The parent knows some earlier results but does not assign reference labels. Agents are not independent human experts.

Reference evidence uses fresh chemistry-source retrieval and standalone structure validation, never the engine's modules or OPSIN output. One database hit is insufficient for EXACT. Source agreement, identifier consistency, semantic granularity, original-name correspondence and form preservation must all be considered. PubChem and NCI can share upstream data, so agreement between them is recorded as potentially dependent, not automatically independent evidence. Missing, malformed or conflicting reference evidence remains explicit. Every source alias receives SAME, DIFFERENT or UNRESOLVED; unresolved is not a negative assertion.

Reference outcomes assess the best-supported discrete molecular identity independent of the engine's current query budget or extra narrow admission envelope. Thus a reference-EXACT/engine-UNRESOLVED case may be intentional abstention, not an unsafe decision. Contradictory aliases need not invalidate a well-supported preferred-name identity. Broader material families, polymers, alloys and mixtures are outside scope.

Each packet is frozen as reference.json plus FROZEN.json containing its SHA256, record count and UTC timestamp. Only after all three files are frozen and validated does the comparison program open the existing candidate and registry databases read-only. It verifies hashes before/after and never changes frozen labels. Missing or structurally invalid reference fields are reported, not repaired to match predictions.

Metrics use these definitions:

- Automatic EXACT precision: chemically verified correct admissions divided by adjudicable admissions (correct plus confirmed incorrect); report unresolved reference cases separately and also report a conservative confirmed-correct/all-admissions lower bound. An unresolved reference does not prove the engine wrong. A correct admission needs reference EXACT and exact preserved-graph agreement, not just shared InChIKey.
- False-positive EXACT: incompatible reference EXACT graph, or a substantive reference CONFLICT/OUT_OF_SCOPE/INVALID contradicting automatic admission; list all. Engine EXACT/reference UNRESOLVED is unverified and listed separately.
- False merge: two different reference-EXACT graph identities assigned the same registry Substance ID. Report offending clusters and pairs; denominator is adjudicable coassigned sampled pairs. Other pairs remain unassessed. Standard InChI equality cannot collapse tautomers.
- Alias precision: each source alias occurrence actually promoted by the engine is checked against its blinded SAME/DIFFERENT/UNRESOLVED judgment and reference identity. Report verified-correct/(correct+incorrect), a conservative lower bound over all promotions, and unknown counts. Repeated source occurrences are included; preferred-name insertion alone is not alias promotion.
- Outcome agreement: exact status equality divided by all sampled records; also show identity disagreement within matching EXACT statuses.
- Abstention: engine UNRESOLVED/all sampled records; separately report total non-admission. Counts and metrics describe this enriched sample, not whole-CUMA prevalence.

Spot checks: reproducibly select up to 20 graph-correct EXACT agreements, every confirmed false-positive EXACT, every false merge, and 20 engine-UNRESOLVED cases spread across reference outcomes and sampling strata. If fewer than 20 eligible cases exist, report the shortfall rather than fabricate them.

Recommendation is driven by verified admission and alias precision, confirmed false merges, uncertainty and disagreement mechanisms. Material confirmed identity/alias errors, false merges, or insufficient independent verification preclude READY_TO_SCALE. High observed precision with limited independent evidence or only a small merge denominator supports at most SCALE_WITH_CAUTION. Unresolved references must not be counted as evidence of safety.

The report's conservative screening rule is fixed before comparison: any confirmed adverse admission/alias/merge finding, less than 90% adjudicability of automatic admissions, or less than 90% confirmed-correct coverage of promoted alias occurrences triggers NOT_READY_TO_SCALE. Otherwise the methodological limits cap this agent-adjudicated exercise at SCALE_WITH_CAUTION. These are review-screening criteria, not a statistically certified production safety threshold.

## Pre-unblinding alias evidence audit

The methodology audit, before any predictions were opened, found that initial SAME alias judgments often used one PubChem alias lookup against a separately corroborated preferred structure. This does not independently corroborate the alias spelling. Original frozen judgments remain unchanged. Each still-blinded reviewer therefore supplies a separately frozen `alias_attestations.json` with exact occurrence positions, supporting sources and CORROBORATED_SAME / CORROBORATED_DIFFERENT / INSUFFICIENT. A corroborated result requires an additional curated/primary/supplier assertion of that alias or an explicit synonym mapping, preserving its chemical form; multiple API endpoints alone do not qualify.

All three main packets and all three alias supplements must be frozen before comparison. Alias precision uses only original judgments consistent with the corroborated supplements and a verified subject identity. Unsupported SAME/DIFFERENT claims are unverified, not automatically correct/incorrect. A contradicted subject does not automatically make every promoted alias incorrect: an independently supported SAME alias is incorrect only where the reference exact graph differs from the assigned graph. This is an evidence-quality refinement made before unblinding, not a change to labels or the recommendation thresholds.
